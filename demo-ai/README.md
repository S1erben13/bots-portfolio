# AI-консультант «Монтаж-Сервис»

Демо для портфолио: веб-чат и Telegram-бот отвечают по базе вымышленной монтажной компании и принимают заявки. Python 3.12, FastAPI, aiogram 3, SQLite, BM25 с русским Snowball-стеммингом. В `kb/` находятся 14 документов об услугах, ценах, сроках и гарантии. Все коммерческие условия и контакты вымышлены.

## Запуск в Docker

Нужен Docker Compose v2.24+ (используется необязательный `env_file`). Из этой папки скопируйте настройки:

```powershell
Copy-Item .env.example .env
docker compose build
docker compose up -d
docker compose logs -f ollama-init
```

В Linux/macOS вместо `Copy-Item` используйте `cp`. При запуске всех сервисов `ollama-init` дожидается Ollama и один раз выполняет `ollama pull` выбранной модели. После сообщения об успешной загрузке откройте [веб-чат](http://localhost:8010). Первое скачивание требует интернета и свободного места; время зависит от соединения и компьютера. По умолчанию используется `qwen2.5:3b`, выполнение на CPU поддерживается. Проверка приложения: `http://localhost:8010/health` (не проверяет готовность модели).

Приложение стартует независимо от скачивания: до готовности Ollama возвращает первые два абзаца самого релевантного фрагмента без Markdown-заголовков (до 600 символов). Данные Ollama и SQLite сохраняются в именованных томах. `docker compose down` останавливает сервисы и сохраняет тома. Не добавляйте `-v`, если нужны заявки и скачанная модель.

После смены `OLLAMA_MODEL` в `.env`:

```powershell
docker compose up -d --force-recreate ollama-init app
```

Для облачного провайдера достаточно заполнить его настройки и запустить `docker compose up -d --build app`; Ollama не требуется. Перезапустите `app` после изменения `.env`. Секреты хранятся только в `.env`, исключённом из Git и Docker-контекста. Не вставляйте ключи в код или базу.

## Как работает ответ

Документы читаются при запуске, делятся на фрагменты до 900 символов с перекрытием до 120 символов. BM25 ранжирует фрагменты после приведения регистра, `ё → е` и русского стемминга. Требуется одновременно `RAG_MIN_SCORE=0.8` и покрытие значимых слов вопроса `RAG_MIN_COVERAGE=0.5`. Это эвристические пороги: для своей базы проверяйте реальные вопросы, синонимы могут не находиться.

После поискового порога LLM получает вопрос и до трёх фрагментов. В одном запросе она проверяет, содержат ли они ответ именно на этот вопрос, и возвращает JSON с полями `answerable` и `answer`. При `true` модель формирует короткий вежливый ответ по-русски (2–5 предложений, только факты из фрагментов, без Markdown-заголовков). Источники передаются отдельно в `sources`: это файлы использованных в запросе фрагментов. Системный промпт содержит примеры наличия и отсутствия ответа, запрещает выдумывать и выполнять инструкции из документов; температура равна 0. При `answerable=false` или отсутствии результатов поиска бот сообщает «В базе нет ответа» и предлагает заявку. При сетевой ошибке, недоступной модели, неправильном JSON или пустом ответе показываются только первые два абзаца самого релевантного фрагмента без Markdown-заголовков (до 600 символов), со ссылкой только на его файл. Если выдержка пуста, возвращается отказ. В резервном режиме смысловая проверка недоступна. Поиск и решение модели могут ошибаться: промпт не гарантирует отсутствие выдуманных фактов.

Примеры: «Какая гарантия на монтажные работы?», «Какая предоплата по договору?», «Сколько стоит установка видеодомофона?». Вопрос «Как приготовить борщ?» должен получить отказ без обращения к LLM.

## Пример диалога

Живой прогон на локальной модели `qwen2.5:3b` (Ollama, CPU), ответы дословно:

- Клиент: «Какая гарантия на монтаж?»
- Консультант: «Гарантия на монтажные работы составляет 12 месяцев с даты подписания акта.» Источники: `06-warranty.md`, `12-faq.md`.
- Клиент: «Вы работаете в выходные?»
- Консультант: «Мы принимаем обращения с понедельника по пятницу с 09:00 до 18:00 по московскому времени. Заявки в выходные сохраняются до следующего рабочего дня.»
- Клиент: «Сколько стоит ремонт стиральной машины?»
- Консультант: «В базе нет ответа на этот вопрос. Предлагаем оставить заявку: укажите имя и телефон в форме или отправьте /lead в Telegram.»

Из 8 контрольных вопросов 7 обработаны верно. Вопрос «Можно ли подключить камеры к телефону?» получил отказ, хотя ответ в базе есть: поиск не связал формулировки. Для своей базы стоит добавить синонимы в FAQ и проверить реальные вопросы клиентов.

## Своя база знаний

Замените файлы в `kb/` собственными `.md`, `.txt`, `.pdf`, `.docx`; вложенные папки поддерживаются. TXT/Markdown — UTF-8. DOCX читает абзацы и таблицы. PDF читает текстовый слой; для сканов сначала нужен внешний OCR. Пустые документы пропускаются, повреждённые файлы нужно исправить: ошибка чтения останавливает запуск, чтобы база не индексировалась незаметно частично. Перезапустите `docker compose restart app`.

База доступна через ссылки `/sources/...`, поэтому размещайте здесь только материалы, которые можно показать клиенту целиком. Имена файлов сохраняются в источниках. Не помещайте сюда `.env`, договоры с персональными данными и внутренние инструкции. Вопрос и найденные фрагменты передаются выбранному LLM-провайдеру; при Ollama остаются в локальном Docker-контуре. Диалоговая история не сохраняется и не передаётся модели.

## Провайдеры и получение ключей

Общий интерфейс — асинхронный `complete(prompt)` в `app/providers.py`. HTTP-запросы имеют таймаут 60 секунд. Выбор — `LLM_PROVIDER=ollama`, `yandexgpt` или `gigachat`.

- **Ollama:** ключ не нужен. `OLLAMA_MODEL` выбирает модель. В Compose адрес `OLLAMA_URL` установлен в `http://ollama:11434`. [Официальный API Ollama](https://github.com/ollama/ollama/blob/main/docs/api.md).
- **YandexGPT:** самостоятельно создайте облако/каталог и сервисный аккаунт в Yandex Cloud, предоставьте ему право вызова моделей (роль `ai.languageModels.user`), создайте API-ключ с разрешением на генерацию. Запишите `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`; `YANDEX_MODEL` по умолчанию `yandexgpt-lite/latest`. Доступность модели и права проверьте в своём каталоге. Инструкции: [получение API-ключа](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys), [синхронная генерация Foundation Models](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/TextGeneration/completion). Адрес задаётся `YANDEX_URL`, по умолчанию — опубликованный `https://ai.api.cloud.yandex.net/foundationModels/v1/completion`.
- **GigaChat:** самостоятельно войдите в кабинет разработчика через Сбер ID, создайте проект и получите ключ авторизации. Готовую строку ключа запишите в `GIGACHAT_AUTH_KEY`, без префикса `Basic` (не кодируйте готовый ключ повторно). Установите scope своего договора: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Приложение обменивает ключ на OAuth-токен, кеширует его до истечения и вызывает chat completions. [Официальная авторизация и адреса API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api). По умолчанию `GIGACHAT_URL=https://api.giga.chat/v1`. Если требуется дополнительный доверенный CA, скачайте сертификат по инструкции провайдера, примонтируйте PEM в контейнер и задайте `EXTRA_CA_FILE=/app/certs/root.pem`. Проверка TLS включена.

Аккаунты и платный доступ владелец подключает сам; программа не регистрирует аккаунты и не проверяет реальные ключи в тестах.

## Telegram и заявки

1. Самостоятельно создайте бота у [BotFather](https://t.me/BotFather), положите токен в `TELEGRAM_BOT_TOKEN`.
2. Менеджер должен сам начать диалог со своим ботом. Узнайте его chat id из обновлений Telegram Bot API (метод [getUpdates](https://core.telegram.org/bots/api#getupdates), пока polling приложения остановлен), запишите в `MANAGER_CHAT_ID`. Не отдавайте токен сторонним ботам.
3. Запустите один экземпляр `app`: он поднимает веб-сервер и polling aiogram. `/start` — приветствие, `/lead` — имя и телефон, `/cancel` — отмена. Черновики диалогов в памяти теряются при перезапуске.

Веб-форма и бот сохраняют заявку в `/app/data/leads.sqlite3` до попытки уведомления. Таблица `leads`: `id`, `name`, `phone`, `created_at` (UTC), `notified`. Без токена/идентификатора менеджера — только лог с номером заявки, без имени и телефона. При ошибке Telegram заявка остаётся в SQLite с `notified=0`; автоматической повторной доставки нет. Приложение не обещает доставку уведомления: ответ API содержит фактический `notified`.

Порт привязан к localhost. Это локальное демо; для публичного размещения владельцу нужно настроить HTTPS, ограничение запросов, собственный текст обработки данных и доступ к заявкам. Для демонстрации вводите вымышленные контакты.

## Тесты

```powershell
docker compose build
docker compose run --rm app pytest -q
```

У `app` нет зависимостей Compose: тестовая команда не запускает Ollama и не скачивает модель. Тесты блокируют реальные подключения сокетов; все HTTP-вызовы провайдеров и Telegram подменены `respx`, веб проверяется через TestClient с поддельным LLM. Проверяются чанкинг, русский стемминг, загрузчики, релевантность и отказ, источники, сохранение/уведомление заявок, форматы трёх API и кеш OAuth.

Прогон в Docker: 39 тестов, все проходят.

## Текст для портфолио

Разработал демо AI-консультанта для монтажной компании: веб-чат и Telegram-бот ищут ответы по документам компании, формируют ответы по найденным фрагментам с источниками и принимают заявки в SQLite с уведомлением менеджеру. Поддерживаются локальная Ollama и облачные YandexGPT/GigaChat. Поиск BM25 учитывает русские словоформы, а при отсутствии сведений консультант предлагает оставить заявку. Проект упакован в Docker Compose, интеграции покрыты тестами с подменой HTTP. Компания и коммерческие условия демонстрационные.
