# Демо: Telegram-бот онлайн-записи

Python 3.12, aiogram 3, FastAPI и SQLite. Демонстрация для портфолио: клиент выбирает услугу, мастера или «любого», дату в ближайшие 14 дней, время, вводит имя и телефон, затем подтверждает запись и получает номер.

## Быстрый запуск в Docker

Из этой папки в PowerShell:

```powershell
Copy-Item .env.example .env
```

Самостоятельно задайте в `.env` свой `ADMIN_PASSWORD`. Для проверки админки токен Telegram не требуется. Затем:

```powershell
docker compose up --build -d
docker compose logs -f booking
```

Откройте http://localhost:8030/admin — логин из `ADMIN_USER`, пароль из `ADMIN_PASSWORD`. `/health` возвращает состояние HTTP-сервера. Порт опубликован только на localhost. Для внешнего доступа потребуется HTTPS через обратный прокси: Basic Auth передаёт учётные данные с каждым запросом.

На первом запуске автоматически создаются 2 мастера и 4 услуги: стрижка (45 мин.), укладка (30 мин.), окрашивание (120 мин.), уход (60 мин.). Демо-график: пн–сб 09:00–18:00, перерыв 13:00–14:00; воскресенье — выходной. Повторное заполнение не меняет существующие данные.

## Telegram

1. Самостоятельно откройте официальный [@BotFather](https://t.me/BotFather), отправьте `/newbot`, выберите имя и username.
2. Сохраните выданный токен только в `BOT_TOKEN` файла `.env`. Не отправляйте его в чат и не добавляйте в Git.
3. Пересоздайте контейнер: `docker compose up -d --force-recreate`.
4. Откройте своего бота, отправьте `/start`. Команда `/id` покажет ID вашего личного чата. Укажите его в `ADMIN_CHAT_ID` и снова пересоздайте контейнер. Администратор должен предварительно начать диалог с ботом.

Бот обслуживает личные чаты. Команды: `/start`, `/menu`, `/id`. Телефон можно отправить своей контактной карточкой через «Поделиться контактом» или ввести вручную. Проверяется формат: 10–15 цифр с необязательным `+`; принадлежность вручную введённого номера не подтверждается. На этапе подтверждения показаны услуга, мастер, дата, имя и телефон. «Мои записи» показывает историю, позволяет отменить запись или перенести её с сохранением номера.

## Консольная демонстрация без Telegram

```powershell
docker compose run --rm booking python -m booking.seed_demo
docker compose run --rm booking python -m booking.simulate
docker compose run --rm booking python -m booking.simulate --auto
```

Интерактивный адаптер проходит те же шаги общей модели диалога, что и бот. `--auto` выбирает первый свободный слот, использует вымышленные данные и создаёт настоящую демо-запись в локальной БД с user_id `10001`. Токен и отправка сообщений для этого не нужны. При включённом боте настроенные уведомления из этой общей БД могут быть отправлены фоновым обработчиком; для полностью изолированного прогона используйте отдельную временную БД:

```powershell
docker compose run --rm -e DB_PATH=/tmp/simulation.sqlite3 booking python -m booking.simulate --auto
```

## Админка и правила расписания

- `/admin`: список на выбранный день или 7 дней с указанной даты, отмена и отметки «пришёл / не пришёл».
- `/admin/catalog`: создание, чтение, изменение и удаление услуг и мастеров; изменение недельного графика, перерывов и выходных на конкретные даты.
- Удаление архивирует услугу/мастера: новые записи недоступны, история и действующие записи сохраняются. Изменение графика само по себе не отменяет существующие записи. Новый мастер появляется без рабочего графика: сначала настройте дни.
- Все мастера оказывают все услуги. Длительность услуг и начало рабочих интервалов кратны 15 минутам. Услуга полностью помещается в рабочее время, не пересекает перерыв и другие записи; стыкующиеся записи разрешены.
- При «любом мастере» показываются доступные пары времени и мастера. Итоговый мастер известен до подтверждения.
- Клиент меняет только собственные подтверждённые записи не позднее чем за `CANCEL_HOURS` часов; ровно на границе изменение разрешено. Для переноса новое время также должно быть не ближе этого срока. Администратор может отменить подтверждённую запись без временного ограничения.
- Время локальное для `TIMEZONE`, по умолчанию `Europe/Moscow`. Эта демоверсия рассчитана на часовой пояс без сезонного перевода часов; хранение — локальное время с точностью до минуты.

Защита от двойной записи: `BEGIN IMMEDIATE`, повторная проверка доступности внутри транзакции, частичный уникальный индекс `(master_id, starts)` и таблица занятых 15-минутных интервалов с уникальным ключом `(master_id, tick)`. Последняя защищает и от совпадения части услуги разной длительности. Перенос освобождает старые интервалы и занимает новые в одной транзакции; при ошибке сохраняется старая запись.

## Напоминания и уведомления

При заданном `BOT_TOKEN` один фоновый обработчик раз в 30 секунд ставит напоминания за 24 часа и за 2 часа в постоянную SQLite-очередь. Для записи, созданной ближе чем за 24 часа, первое напоминание придёт на ближайшем проходе; ближе чем за 2 часа — только напоминание «2 ч». Просроченные напоминания пропускаются. Отмена и перенос удаляют напоминания для старого времени.

Новые записи, отмены и переносы создают уведомления в `ADMIN_CHAT_ID`. Ошибки отправки оставляют сообщения для повторной попытки. В очереди уникальна пара «запись / тип напоминания». Доставка имеет семантику «как минимум один раз»: при сбое между успешной отправкой в Telegram и отметкой в SQLite возможно повторное сообщение. Без токена очередь сохраняется, сетевых отправок нет. Запускайте один экземпляр приложения/обработчика на эту БД.

## Настройки

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен бота; пустой — только админка и консоль |
| `ADMIN_CHAT_ID` | Личный чат администратора; пустой — уведомления администратору отключены |
| `ADMIN_USER` | Логин админки, по умолчанию `admin` |
| `ADMIN_PASSWORD` | Обязательный пароль, задаётся владельцем |
| `CANCEL_HOURS` | Срок отмены/переноса, по умолчанию 3 |
| `TIMEZONE` | Часовой пояс, по умолчанию `Europe/Moscow` |
| `DB_PATH` | Путь к SQLite; Compose фиксирует `/app/data/booking.sqlite3` в постоянном томе |

Обычный `docker compose down` сохраняет том. `docker compose down -v` удалит все записи и каталог — используйте только для намеренного сброса демо. `.env` и локальная `data/` исключены из Git и Docker-контекста.

## Проверка

```powershell
docker compose --env-file .env.example config --quiet
docker compose build
docker compose run --rm booking python -m compileall -q booking tests
docker compose run --rm booking python -m pytest -q
docker compose run --rm -e DB_PATH=/tmp/simulation.sqlite3 booking python -m booking.simulate --auto
```

Тесты используют временные БД, фиксированные часы и поддельную отправку Telegram: генерация слотов, длительности, перерыв, воскресенье и индивидуальный выходной; пересечения и соседние интервалы; две параллельные попытки на один/пересекающийся слот; уникальность занятых интервалов; выбор любого мастера; права и граница отмены; атомарный перенос; напоминания, повтор доставки и просрочка; полный консольный диалог; Basic Auth, защита форм, экранирование HTML, CRUD и расписание.

Прогон в Docker: 19 тестов, все проходят; консольный сценарий `python -m booking.simulate --auto` проходит целиком.

## Текст для портфолио

> Telegram-бот онлайн-записи для салона или сервисной компании: выбор услуги, мастера, даты и свободного времени, контакт клиента и подтверждение с номером записи. Личный кабинет с отменой и переносом, напоминания и уведомления администратору. Веб-панель показывает записи на день и неделю, позволяет вести услуги, мастеров и расписание. SQLite-транзакции и уникальные ограничения защищают от двойного бронирования. Демо работает в Docker; предусмотрен консольный сценарий без Telegram.

Это описание реализованных возможностей демо, а не кейс внедрения: реальные клиенты, показатели продаж и экономия времени не заявляются.
